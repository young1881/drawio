# drawio-diagram

一个 Claude Code **Skill**，用于把自然语言描述生成为专业、美观、可直接导入的 Draw.io
（`.drawio` / mxGraph XML）图表，覆盖架构图、流程图、统计图、矩阵/对比/思维导图等场景。

## 这是什么

`.claude/skills/drawio-diagram/` 是一个标准的 Claude Code 技能。当你让 Claude「画一张架构图 /
流程图 / 柱状图……」或提到 drawio / diagrams.net 时，它会被自动触发，按照统一的设计系统
（配色、样式、布局网格）输出一个完整的 `.drawio` 文件，并在交付前用校验脚本检查合法性。

设计思路：**形式服务内容** —— 先判断内容要表达的是「连接 / 顺序 / 数量 / 交叉分类」中的哪一种，
再选择对应的布局族，最后落地成 mxGraph XML。

## 目录结构

```
.
├── .claude/skills/drawio-diagram/
│   ├── SKILL.md                # 技能主文件：工作流、基础骨架、共享设计系统、布局选择表、校验步骤
│   ├── references/             # 按图表族拆分的模板与布局公式（按需加载）
│   │   ├── architecture.md     # 架构/拓扑：分层、中心辐射、分组依赖 + 形状/连线速查
│   │   ├── flowchart.md        # 流程/时序：线性分支、泳道、状态机、时间线 + 折返连线路由
│   │   ├── charts.md           # 统计图：柱状/饼图/折线 —— 含精确的数值→像素换算公式
│   │   └── matrix.md           # 矩阵/对比：二维矩阵、对比表、2×2 象限、思维导图、看板
│   └── scripts/
│       └── validate_drawio.py  # 校验脚本：XML 合法性、根节点、id 唯一、引用可解析、几何完整
├── .gitignore
└── README.md
```

## 安装 / 使用

技能位于项目本地的 `.claude/skills/`，在本仓库目录下启动 Claude Code 即可生效；
若想全局可用，复制到 `~/.claude/skills/` 即可。

触发方式 —— 直接用自然语言描述需求，例如：

- 「画一张这个系统的分层架构图：前端、服务层、数据层」
- 「把这个登录流程做成流程图，带校验失败的分支」
- 「用 Q1=80 Q2=140 Q3=110 Q4=200 画个季度营收柱状图」
- 「做一个能力维度 × 生命周期阶段的二维矩阵」

Claude 会读取 `SKILL.md`，按内容选择布局族并打开对应的 `references/` 模板，生成 `.drawio`
文件后自动运行校验。

## 校验脚本

生成的文件可独立校验：

```bash
python3 .claude/skills/drawio-diagram/scripts/validate_drawio.py 你的图.drawio
```

检查项：XML 是否良构、必备的 `id="0"`/`id="1"` 根节点、id 是否唯一、每个
`source`/`target`/`parent` 是否指向存在的 id、顶点是否带几何信息。返回码 `0` 表示全部通过，
`1` 表示存在错误（这些正是会导致 draw.io 打不开文件或悄悄丢图形的问题）。

仅依赖 Python 3 标准库，无需安装第三方包。

## 设计系统要点

- **配色按「分组」而非「单元」**：6 个色系（蓝/绿/紫/琥珀/粉红/中性），每个含强填充、浅填充、
  容器底色与配套深色字色；同一逻辑分组复用同一色系。
- **可复用样式字符串**：标题、副标题、主框、叶子框、容器、深色横幅、连线，均有现成片段。
- **布局网格**：元素对齐到 10 的倍数，同层等间距；顶部留标题区，底部可放图例/小结。
- **渐进式加载**：`SKILL.md` 常驻上下文，详细模板只在用到对应图表族时才读取，控制 token 开销。

## 生成的文件如何查看

输出的 `.drawio` 文件可用 [diagrams.net](https://app.diagrams.net/) 直接打开，或用 VS Code 的
Draw.io Integration 插件预览/编辑。
